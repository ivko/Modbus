Modbus Slave User Manual

Version 1.0 · Modbus slave simulator with value and error simulation. Companion of Modbus Master.

1. Introduction

Modbus Slave plays the role of one or more Modbus devices (slaves, servers). A master such as a SCADA system, an HMI, a PLC or Modbus Master sends requests; Modbus Slave answers them from the values shown in its windows. Use it to develop and test master software without the real devices, or to reproduce faults that are hard to provoke on real hardware.

  • Serial RTU and ASCII, Modbus TCP, Modbus UDP, RTU/ASCII over TCP and UDP, and Modbus/TCP Security (TLS).
  • Any number of slave IDs, each with its own coils, discrete inputs, holding registers and input registers.
  • Functions 01 to 06, 08, 11, 15, 16, 17, 22, 23 and 43/14.
  • Value simulation per cell: increment, decrement, random, sine, ramp and toggle.
  • Error simulation per slave: response delay, missing answers, wrong CRC/LRC, truncated answers, answers from another slave ID and forced exception codes.
  • The same display formats, scaling, conditional colors, value names, charts and traffic window as Modbus Master.
  • Automation with the same member names as the Modbus Slave (Witte Software) automation interface.

2. Quick start

  1. Start ModbusSlave.exe. A window for slave ID 1, holding registers 0 to 9 opens.
  2. Press F3, choose Modbus TCP/IP, port 1502 (ports below 1024 may be blocked or used by other programs), and press OK. The status bar shows Listening.
  3. Double click a value and enter a number.
  4. Read it from a master, for example with Modbus Master or from a command prompt: 
    mbm read --tcp 127.0.0.1:1502 --count 10

Windows Firewall asks whether Modbus Slave may accept connections the first time it listens on a network interface. Allow it for private networks if masters on other computers must reach it.

3. Windows and cells

Each tab is a slave window. It shows one block of one table of one slave ID. Several windows may show different blocks of the same slave, or different slaves.

ID = 1: F = 03: Requests = 214: Errors = 3: Simulated faults = 3

The status line counts the requests that reached this window and the ones that ended in an exception or a simulated fault. A second line appears in red while the slave is not listening, in listen-only mode, or while error simulation is on.

The Name column is free text. Values change when the master writes, when value simulation runs, or when you edit them.

4. Connection setup

Connection > Connect (F3) sets up and starts the slave. Quick Connect (F5) starts it again with the last settings, Disconnect (F4) stops it.

SettingMeaning
ConnectionSerial port, Modbus TCP/IP, Modbus UDP/IP, RTU/ASCII over TCP/IP or UDP/IP, Modbus/TCP Security
Serial settingsPort, baud rate, data bits, parity, stop bits, RTU or ASCII mode. They must match the master exactly.
Any addressListen on all network interfaces. Turn it off and enter an IP address to listen on one interface only (e.g. 127.0.0.1 for local tests).
Port502 is the Modbus standard, 802 for Modbus/TCP Security.
Ignore unit IDAnswer requests for slave IDs without a window with the first slave. Many TCP masters send unit ID 0 or 255.
Server certificateModbus/TCP Security: a PFX file, or a PEM certificate with its key file.
Require a client certificateMasters must present a certificate. With a trusted client CA, only certificates signed by that CA are accepted; without it, any certificate is accepted.

On a serial line only one program can own the port. Use a pair of virtual COM ports (com0com or similar) to connect a master on the same computer.

5. Slave definition

Setup > Slave Definition (F8) sets what the current window represents.

FieldMeaning
Slave ID1 to 247 on a serial line (up to 255 allowed). TCP devices commonly use 1, 0 or 255.
FunctionThe table: 01 coils, 02 discrete inputs, 03 holding registers, 04 input registers. Coil windows also accept writes 05 and 15; holding register windows accept 06, 16, 22 and 23.
Address, QuantityFirst address and number of values, 1 to 10000.
DisabledThe slave does not answer while all its windows are disabled. Use it to simulate a device that was switched off.

Addresses

Addresses count from 0, as in the protocol. With PLC addresses on, you can type and see 40001-style addresses: 40001 is holding register 0, 30001 input register 0, 10001 discrete input 0, 1 coil 0.

Strict addressing

With Setup > Strict Addressing on (the default), only addresses shown in a window exist. A request that touches any other address gets exception 02 Illegal Data Address, as a real device would. Adjacent windows count as one block. Turn it off to accept every address 0 to 65535 of every table of a defined slave.

6. Changing values

  • Double click a register value, or press Enter, and type the new value in the cell's format (e.g. 12.5 in a float cell).
  • Double click a coil or input to toggle it. With several selected, all get the opposite of the first.
  • File > Import Values from CSV loads address;value rows (raw register values) into the current window. Files saved with Export to CSV can be imported again.

7. Value simulation

Select cells and choose Simulation > Value Simulation (F9). The slave then changes the values by itself:

ModeBehaviour
Increment / DecrementAdds or subtracts Step every interval and wraps around between Min and Max.
RandomA random value between Min and Max every interval.
SineA sine wave between Min and Max with the given period.
RampRises from Min to Max over the period, then starts again.
ToggleSwitches between Min and Max (0 and 1 for coils).

Simulation uses the cell's display format: set a cell to 32-bit Float first, and Sine produces a float that covers two registers. Simulation > Auto Increment and Auto Decrement add 1 every second over the whole range of the format. Simulation settings are saved in the workspace.

8. Error simulation

Setup > Error Simulation (Ctrl+E) makes the slave of the current window misbehave on purpose. Use it to check that a master reports errors, retries, times out and recovers correctly. The settings apply to all windows of that slave ID.

SettingWhat the master sees
Response delay, random extra delaySlow answers. A delay longer than the master's response timeout gives a timeout; a delay just below it tests the margin.
No response [%], every Nth requestTimeouts. "Every 3rd" gives a regular pattern that is easy to see in a log.
Wrong CRC/LRC [%]A CRC error (RTU) or LRC error (ASCII). On TCP and UDP, which carry no checksum, the MBAP protocol identifier is made invalid so the master must reject the frame.
Truncated answer [%]The end of the frame is missing: "insufficient bytes" or a timeout.
Answer with another slave ID [%]A response error: the answer comes from the wrong device.
Exception, only for function, exception [%]An exception response instead of the data, e.g. 04 Server Device Failure or 06 Server Device Busy. The request is not executed.

Faults are chosen per request in this order: no response, exception, then one of checksum / truncate / wrong ID; the delay applies to every answer. Simulated faults appear in the status line and in the traffic window with a note.

Diagnostics also behave like a real serial device: sub-function 04 puts the slave in listen-only mode (no answers at all) until a master sends sub-function 01.

9. Device identification

Setup > Device Identification sets what the slave reports:

  • Function 43/14 Read Device Identification: vendor name, product code and revision (basic), vendor URL, product name, model name and user application name (regular). Stream access (codes 1 and 2) and individual access (code 4) are supported.
  • Function 17 Report Server ID: the server ID text and the run indicator.

11. Display formats and cells

Display formats (signed, unsigned, hex, binary, 32/64-bit integers, float and double in four byte orders), scaling, conditional colors and value names work exactly as in Modbus Master. See the Modbus Master manual: display formats and format numbers, scaling, conditional colors, value names.

The display format also decides how you enter values and how value simulation encodes them.

12. Real-time charting

Select cells and press Ctrl+L (Display > Link to Chart). Zoom with the mouse wheel, pan by dragging, double click to follow live data, and export the series as CSV or the chart as PNG. Details: charting in the Modbus Master manual.

13. Logging

Setup > Log writes the window's values to a CSV file at most once per interval, optionally only when a value changed. Logging Off stops it.

14. Workspaces and CSV

File > Save Workspace (Ctrl+S) writes a *.mms file with the connection, all windows with their cell settings and value simulation, the error simulation and device identification of each slave, and the current values. Opening it restores the complete simulated plant. Certificate passwords are never saved. File > Export to CSV saves address, name, formatted value and raw value of the current window.

15. Communication traffic

Display > Communication (F7) shows every request received (Rx) and answer sent (Tx). Requests that were not answered, damaged requests and simulated faults are marked with a note.

16. Automation (COM)

Register once with Tools > Register Automation, or ModbusSlave.exe /regserver. The object names are ModbusSlave.Application and ModbusSlave.Document. With /regserver /compat the names Mbslave.Application and Mbslave.Document are registered too, so scripts written for Modbus Slave by Witte Software run unchanged. Do not do that while that program is installed and in use.

Example (VBScript)

Set app = CreateObject("ModbusSlave.Application")
app.Connection = 1 : app.ServerPort = 1502 : app.AnyAddress = 1
Set doc = CreateObject("ModbusSlave.Document")
doc.SetupHoldingRegisters 1, 0, 20
doc.ByteOrder = 0
doc.Floats(0) = 21.5           ' registers 0-1
doc.SRegisters(2) = -7
doc.AutoIncrement(3) = True
app.OpenConnection
doc.ShowWindow

In Python (pywin32) call methods with parentheses and set indexed values as doc.SRegisters(2, -7).

17. Testing a master

A typical test of master software against Modbus Slave:

  1. Build the device in windows: one per table and address block, with names and formats. Save it as a workspace.
  2. Let value simulation move the measurements (sine for temperatures, random for noisy inputs, increment for counters).
  3. Check normal operation, then turn on error simulation step by step: a delay near the master's timeout, 10 % missing answers, 5 % CRC errors, then exception 06 (busy) for write functions only.
  4. Watch the traffic window on both sides. Modbus Master shows the same frames from the master's point of view.

For automated tests, drive both programs from a script: Modbus Slave through automation, the master under test as usual, or Modbus Master's mbm command line, whose exit codes tell exactly what happened (0 ok, 1 exception, 2 communication error).
