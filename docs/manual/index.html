Modbus Master User Manual

Version 1.0 · Modbus master for test, commissioning and scripting.

1. Introduction

Modbus Master is a Modbus master (client): it sends requests to slave devices (servers) such as PLCs, drives, meters and sensors, and shows the answers. It has three parts that share the same Modbus engine:

  • ModbusMaster.exe, the Windows program with data windows, charts, logging, scans and the Test Center.
  • mbm.exe, a command line tool for batch files, PowerShell and any other scripting language. See chapter 20.
  • Automation (COM): Excel VBA, VBScript, Python and other COM clients can control the program. The interface uses the same member names and numbers as Modbus Poll. See chapter 19.

Supported connections

  • Serial port, RTU or ASCII mode (RS-232, RS-485 through USB converters).
  • Modbus TCP/IP and Modbus UDP/IP.
  • Modbus RTU or ASCII frames over TCP/IP or UDP/IP (serial device servers and gateways).
  • Modbus/TCP Security: Modbus TCP over TLS 1.2/1.3 with X.509 certificates.

System requirements

Windows 10 or 11, 64-bit, with the .NET 10 Desktop Runtime. A self-contained build needs no runtime.

2. Quick start

  1. Start ModbusMaster.exe. An empty data window called Mbpoll1 opens.
  2. Press F3 (Connection > Connect). Choose the connection type and settings and press OK. The status bar turns green when the connection is open.
  3. Press F8 (Setup > Read/Write Definition). Enter the slave ID, function, address, quantity and scan rate. Example: slave 1, function 03, address 0, quantity 10, 1000 ms.
  4. The window now reads the registers every scan rate. Double click a value to write a new one.
  5. Press Ctrl+N for more windows, for example another slave ID or another address range. All windows share the connection.

No device at hand? Start the built-in simulator from a command prompt and connect to 127.0.0.1 port 1502:

mbm serve --port 1502 --simulate

With --simulate, input registers 0 to 2 change every second, so you can try charts and logging.

3. Windows and cells

Each tab is one data window. It reads or writes one block of data with its own slave ID, function, address, quantity and scan rate. You can open as many windows as you need.

The top of each window shows a status line:

Tx = 128: Err = 2: ID = 1: F = 03: SR = 1000ms

Tx counts the requests sent, Err the failed ones. Below it, a red line shows the last error, for example Timeout error or Exception 02: Illegal Data Address. The line disappears when the next request succeeds.

Name cells

The Name column is free text. Click it and type a name such as "Pump speed". Names are saved in the workspace and appear in logs, CSV exports and chart legends.

Value cells

The Value column shows the data in the chosen display format. Select one or more rows (Shift/Ctrl+click) before you change the format, scaling, colors or value names. Double click a value, or press Enter, to write to it:

  • Coils (function 01): opens Write Single Coil with the opposite value.
  • Holding registers (03, 23): opens Write Register in the cell's format. 32 and 64-bit formats are written with function 16.
  • Discrete inputs (02) and input registers (04) are read-only.
  • Write windows (05, 06, 15, 16): changes the value that the window writes. See write windows.

When a 32 or 64-bit format starts at a cell, the following cells it covers stay empty.

Press F1 in any dialog to open the matching chapter of this manual.

With function 05, 06, 15 or 16 the window writes its values every scan rate instead of reading. Double click a value to change what is written. Use Read/Write disabled plus F6 to write only when you choose.

7. Display formats

Select cells and choose a format from the Display menu. Shortcuts: Alt+S signed, Alt+U unsigned, Alt+H hex, Alt+B binary.

A register holds 16 bits. Larger values use 2 registers (32-bit integers and floats) or 4 registers (64-bit integers and doubles). Devices disagree about the order of the bytes, so each large format comes in four byte orders. Take the 32-bit value 123456789 (hex 07 5B CD 15) as an example:

Byte orderBytes on the wireRegistersTypical devices
Big-endian (ABCD)07 5B CD 15075B CD15The Modbus standard; most PLCs
Little-endian byte swap (CDAB)CD 15 07 5BCD15 075B"Word swapped"; many meters and drives
Big-endian byte swap (BADC)5B 07 15 CD5B07 15CDRare
Little-endian (DCBA)15 CD 5B 0715CD 5B07Rare

If a float looks like nonsense, try CDAB first.

8. Scaling

Display > Scaling converts raw values into engineering units with a straight line:

value = ScaledMin + (raw - RawMin) × (ScaledMax - ScaledMin) / (RawMax - RawMin)

Example: a 4-20 mA input reads 0 to 4000. Set raw 0 to 4000 and scaled 4 to 20 with 1 decimal; a raw value of 2000 shows 12.0. Scaling is applied after the display format, so it also works for floats and 32-bit integers. Charts and logs use the scaled value.

9. Conditional colors

Display > Conditional Colors sets a background and text color for the selected cells, plus two rules. Rule 1 is checked first, then rule 2. If no rule matches, the normal colors are used.

RuleMatches when

and(value AND compare) ≠ 0. Use it to highlight a status bit, e.g. compare 4 for bit 2.

10. Value names

Display > Value Names shows a text instead of a number, one entry per line:

0=Stopped
1=Running
2=Fault

Values without an entry are shown as numbers. Hex values such as 0x10=Alarm are allowed.

12. Address scan

Tools > Address Scan finds which addresses of one slave can be read. It reads the range in blocks (default 100). When a block fails with an exception, it retries that block one address at a time. The result lists every readable address with its value. Turn on "Show addresses that return an exception" to also list the failures. Export CSV saves the list.

A large range on a slow serial line takes time: 10000 addresses at 9600 baud with blocks of 100 needs about 100 requests, but each failing block adds up to 100 more.

13. Slave scan

Tools > Slave Scan sends one read to every slave ID in a range and lists the ones that answer. A slave that returns an exception also counts as found: it exists, but does not have that address. Use a short response timeout (e.g. 200 ms) so the scan is fast. On TCP, most devices answer every unit ID.

15. Export to CSV

File > Export to CSV saves the current window: address, name, formatted value and format, separated by semicolons. Excel opens the file directly.

16. Test Center

Functions > Test Center sends any bytes and shows the raw answer. Use it to test devices that do not follow the standard, or to reproduce a problem exactly.

  • Type hex bytes, e.g. 01 03 00 00 00 0A (slave ID, function, data).
  • With Add checksum / header on, the program adds the CRC for RTU, the ':' framing and LRC for ASCII, or the MBAP header for TCP/UDP, depending on the connection.
  • With it off, the bytes are sent exactly as typed. Start with ':' to send ASCII text as typed; CR LF is added.
  • The answer is shown as hex, with a note whether the CRC/LRC is correct and whether it is an exception.
  • Save frequently used strings with Add to list and Save strings. The file is plain text, one string per line; lines starting with # are comments. Double click a string to send it.

17. Data logging

Setup > Log writes the current window to a CSV file. Each row contains the time, the formatted value of each cell (named columns when the cell has a name) and the poll status.

18. Communication traffic

Display > Communication (F7) shows every frame on the wire:

18:02:10.251 Tx: 00 01 00 00 00 06 01 03 00 0A 00 02
18:02:10.265 Rx: 00 01 00 00 00 07 01 03 04 F5 C3 40 48

Serial RTU frames include the CRC; ASCII frames are shown as text. Late answers to an earlier request and incomplete frames are marked. Stop freezes the list, Save writes the full history (last 20000 frames) to a text file.

19. Automation (COM)

Modbus Master is an automation server. Excel, Word, VBScript, Python (pywin32), LabVIEW and other COM clients can create data windows, read and write values and control the connection.

The interface uses the same member names, numbers and DISPIDs as the Modbus Poll automation interface. Scripts written for Modbus Poll work with Modbus Master; only the object names in CreateObject change, or none at all with the compatible names (below).

Registration

Choose Tools > Register Automation, or run once:

ModbusMaster.exe /regserver
ModbusMaster.exe /regserver /compat     (also registers Mbpoll.Application and Mbpoll.Document)
ModbusMaster.exe /unregserver
Object name (ProgID)Object
ModbusMaster.ApplicationConnection setup
ModbusMaster.DocumentOne data window
Mbpoll.Application, Mbpoll.DocumentOptional compatible names, so existing scripts run unchanged

Registration is per Windows user and needs no administrator rights. Programs that run as administrator do not see per-user registrations. If Modbus Poll is installed too, registering the compatible names makes scripts on your user account use Modbus Master. Leave them off to keep both programs, and change the names in your scripts.

When a script creates an object and Modbus Master is not running, Windows starts it hidden. Call ShowWindow to show it. A hidden instance exits when the script releases all objects. If Modbus Master is already running, scripts control the running program.

Modbus Master is 64-bit; 32-bit Excel and 32-bit Python work as well, because the objects live in a separate process.

The index is a register index. Three floats therefore use indexes 0, 2 and 4 and are written with WriteMultipleRegisters(id, address, 6). In VBA write doc.SRegisters(0) = 1. In Python write doc.SRegisters(0, 1) and read doc.SRegisters(0).

In Python always call methods with parentheses: app.OpenConnection(), doc.ReadResult(), doc.GetTxCount(). Without them Python returns the method instead of calling it. Some Modbus Poll examples omit the parentheses; add them when you reuse those scripts.

Examples

The examples folder next to the program contains these scripts ready to run.

Excel VBA

Public app As Object, doc1 As Object, doc2 As Object

Private Sub StartModbus_Click()
    Set app = CreateObject("ModbusMaster.Application")
    Set doc1 = CreateObject("ModbusMaster.Document")
    Set doc2 = CreateObject("ModbusMaster.Document")
    doc1.ReadHoldingRegisters 1, 0, 10, 1000   ' 10 holding registers every 1000 ms
    doc2.ReadCoils 1, 0, 10, 1000              ' 10 coils every 1000 ms
    app.Connection = 1                         ' Modbus TCP/IP
    app.IPAddress = "192.168.1.10"
    app.ServerPort = 502
    If app.OpenConnection() <> 0 Then MsgBox "Connection failed"
End Sub

Private Sub Read_Click()
    Dim n As Integer
    Cells(2, 4) = doc1.ReadResult()
    For n = 0 To 9
        Cells(2 + n, 2) = doc1.SRegisters(n)
        Cells(2 + n, 3) = doc2.Coils(n)
    Next n
End Sub

Private Sub Write_Click()
    doc1.Floats(0) = Cells(2, 6)               ' fills registers 0-1 of the write array
    doc1.WriteMultipleRegisters 1, 100, 2      ' writes them to address 100
End Sub

21. .NET library

Modbus.Core.dll contains the whole Modbus engine. Use it from C#, F# or PowerShell for scripts that need more than mbm offers.

Add-Type -Path "C:\path\to\ModbusMaster\Modbus.Core.dll"
$s = [Modbus.Core.ConnectionSettings]::new()
$s.Kind = "Tcp"; $s.Host = "192.168.1.10"; $s.Port = 502
$c = [Modbus.Core.ModbusConnection]::Create($s)
$c.Open()
$c.ReadHoldingRegisters(1, 0, 10)
$c.WriteSingleRegister(1, 40, 1500)
$c.Dispose()

PowerShell 7.5 or later loads .NET 10 libraries. Windows PowerShell 5.1 cannot; use mbm there.

22. Errors and exceptions

Errors appear in red in the second line of each data window.

Modbus exception codes

An exception means the device received the request and refused it.

CodeNameUsual cause
01Illegal FunctionThe device does not support this function code.
02Illegal Data AddressThe address, or address + quantity, is outside the device's range. Check the address offset (40001 = 0).
03Illegal Data ValueThe quantity or the written value is not allowed.
04Server Device FailureThe device had an internal error while executing the request.
05AcknowledgeThe device accepted a long-running request; poll later.
06Server Device BusyRetry later.
08Memory Parity ErrorDevice memory error.
0AGateway Path UnavailableThe gateway has no route to that unit ID.
0BGateway Target Device Failed To RespondThe gateway forwarded the request but the serial device did not answer.

Communication errors

MessageCheck
Timeout errorNo answer in time. Serial: baud rate, parity, data and stop bits, RTU/ASCII mode, slave ID, wiring (A/B swapped), termination. TCP: IP address, port, unit ID, firewall. Increase the response timeout for slow devices.
CRC/LRC errorThe answer was damaged: noise, wrong baud rate, missing termination, two masters on the bus.
Response from slave ID x, expected yAnother device answered, or the gateway changes the unit ID.
Byte count error / response does not echo the requestThe answer is valid Modbus but not the expected size or address. Some devices limit the quantity per request.
Incomplete responseOnly part of a frame arrived. Increase the response timeout or the delay between polls.
Connection timeout / connection failedThe TCP connection could not be opened. Ping the device and check the port (502, or 802 for TLS).
COMx is in use by another programClose the other program that holds the port.
The serial port is closed. Disconnected USB/serial converter?The adapter was unplugged. Reconnect it and press F5.
TLS connection failedCertificate not trusted, wrong server name, missing or wrong client certificate, or the device needs a different TLS version.
